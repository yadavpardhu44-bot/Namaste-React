# Chapter 12 — Let's Build Our Store (Namaste React)

This chapter introduces **State Management using Redux Toolkit (RTK)** and explains how data flows through a Redux application.

---

# 1. `useContext` vs Redux

Both are used for sharing data across components without prop drilling, but they serve different purposes.

---

## What is `useContext`?

React's built-in state-sharing mechanism.

### Example

```jsx
const UserContext = createContext();

function App() {
  return (
    <UserContext.Provider value={"Pardhu"}>
      <Header />
    </UserContext.Provider>
  );
}
```

Accessing data:

```jsx
const user = useContext(UserContext);
```

---

## What is Redux?

A centralized state management library.

```txt
Store
 ├── Cart
 ├── User
 ├── Products
 └── Orders
```

Any component can access and update the store.

---

## Comparison

| Feature                  | useContext        | Redux      |
| ------------------------ | ----------------- | ---------- |
| Built into React         | ✅                 | ❌          |
| Setup Complexity         | Low               | Medium     |
| Best for                 | Small/Medium apps | Large apps |
| DevTools Support         | ❌                 | ✅          |
| Middleware Support       | ❌                 | ✅          |
| Performance Optimization | Limited           | Better     |
| Centralized State        | Partial           | Complete   |

---

## When to Use?

### useContext

Use when:

* Theme switching
* User information
* Language settings
* Small global state

---

### Redux

Use when:

* Shopping cart
* Authentication
* Product management
* Large applications
* Complex state logic

---

## Interview Answer

> useContext helps share data across components, while Redux provides a centralized store with predictable state management, debugging tools, middleware support, and better scalability for large applications.

# 2. Advantage of Redux Toolkit over Redux

Redux Toolkit (RTK) is the official recommended way of writing Redux.

---

## Traditional Redux Problems

Too much boilerplate code.

Example:

### Actions

```js
export const ADD_ITEM = "ADD_ITEM";
```

### Action Creator

```js
export const addItem = (item) => {
  return {
    type: ADD_ITEM,
    payload: item,
  };
};
```

### Reducer

```js
const cartReducer = (state = [], action) => {
  switch (action.type) {
    case ADD_ITEM:
      return [...state, action.payload];

    default:
      return state;
  }
};
```

---

## Redux Toolkit Solution

```js
const cartSlice = createSlice({
  name: "cart",

  initialState: [],

  reducers: {
    addItem: (state, action) => {
      state.push(action.payload);
    },
  },
});
```

Much shorter and cleaner.

---

## Advantages of RTK

### 1. Less Boilerplate

No action types.

No action creators.

No switch statements.

---

### 2. Built-in Immer

Allows writing:

```js
state.push(item);
```

instead of:

```js
return [...state, item];
```

RTK internally keeps state immutable.

---

### 3. Built-in Redux DevTools

Easy debugging.

---

### 4. Better Performance

Optimized architecture.

---

### 5. Easier Learning Curve

Cleaner syntax.

---

## Interview Answer

> Redux Toolkit reduces boilerplate code, provides built-in Immer support, integrates Redux DevTools, and simplifies Redux development while following best practices.

# 3. Explain Dispatcher

Dispatcher is responsible for sending actions to the Redux store.

In React, we use:

```jsx
const dispatch = useDispatch();
```

---

## Example

```jsx
const dispatch = useDispatch();

dispatch(addItem(item));
```

---

## Flow

```txt
Button Click
     ↓
Dispatch Action
     ↓
Reducer
     ↓
Store Updated
     ↓
UI Re-render
```

---

## Example

```jsx
<button
  onClick={() => dispatch(addItem(pizza))}
>
  Add Item
</button>
```

---

## Interview Answer

> Dispatcher is a mechanism used to send actions to the Redux store so reducers can update the state.

---

# 4. Explain Reducer

A reducer is a pure function that decides how state changes.

---

## Syntax

```js
(state, action) => newState
```

---

## Example

```js
const cartReducer = (state, action) => {
  switch (action.type) {
    case "addItem":
      return [...state, action.payload];

    default:
      return state;
  }
};
```

---

## Responsibilities

* Receives current state
* Receives action
* Returns new state

---

## Important Rule

Reducers should be:

✅ Pure Functions

```txt
Same Input
    ↓
Same Output
```

No API calls.

No side effects.

No random values.

---

## Example

```js
addItem: (state, action) => {
  state.push(action.payload);
}
```

---

## Interview Answer

> A reducer is a pure function that receives the current state and an action, then returns the updated state.

# 5. Explain Slice

A slice is a portion of the Redux store.

---

## Example Store

```txt
Store
 ├── cartSlice
 ├── userSlice
 ├── productSlice
 └── orderSlice
```

Each slice manages its own state and reducers.

---

## Cart Slice Example

```js
const cartSlice = createSlice({
  name: "cart",

  initialState: [],

  reducers: {
    addItem() {},
    removeItem() {},
    clearCart() {},
  },
});
```

---

## Why Use Slices?

Keeps code modular.

Instead of:

```txt
One Huge Reducer
```

we create:

```txt
Cart Slice
User Slice
Product Slice
```

---

## Interview Answer

> A slice is a logical section of the Redux store containing state, reducers, and generated actions for a specific feature.

# 6. Explain Selector

Selectors are used to read data from the Redux store.

React Redux provides:

```jsx
useSelector()
```

---

## Example

```jsx
const cartItems = useSelector(
  (store) => store.cart.items
);
```

---

## Flow

```txt
Redux Store
     ↓
Selector
     ↓
Component
```

---

## Example

```jsx
const cartItems = useSelector(
  (store) => store.cart
);
```

Now:

```jsx
<h1>Cart ({cartItems.length})</h1>
```

---

## Why Use Selectors?

* Read store data
* Automatic re-render
* Efficient updates

---

## Interview Answer

> A selector is a function that extracts specific data from the Redux store and provides it to React components.

# 7. Explain `createSlice()` and Its Configuration

`createSlice()` is the most important Redux Toolkit API.

It automatically creates:

* Reducers
* Actions
* Action creators

---

## Syntax

```js
createSlice({
  name,
  initialState,
  reducers,
});
```

---

## Example

```js
import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",

  initialState: {
    items: [],
  },

  reducers: {
    addItem: (state, action) => {
      state.items.push(action.payload);
    },

    removeItem: (state, action) => {
      state.items.pop();
    },

    clearCart: (state) => {
      state.items.length = 0;
    },
  },
});

export const {
  addItem,
  removeItem,
  clearCart,
} = cartSlice.actions;

export default cartSlice.reducer;
```

---

## Configuration Properties

### 1. `name`

```js
name: "cart"
```

Used as slice identifier.

Generated action type:

```txt
cart/addItem
cart/removeItem
```

---

### 2. `initialState`

```js
initialState: {
  items: [],
}
```

Defines initial state.

---

### 3. `reducers`

```js
reducers: {
  addItem() {},
  removeItem() {},
}
```

Contains functions that update state.

---

## What `createSlice()` Returns

```js
{
  actions,
  reducer
}
```

### Actions

```js
cartSlice.actions.addItem
```

### Reducer

```js
cartSlice.reducer
```
