# 1. Explore All the Ways of Writing CSS

There are multiple ways to style React applications.

---

## 1. External CSS

Create a separate CSS file.

### style.css

```css
.heading {
  color: blue;
  font-size: 30px;
}
```

### App.js

```jsx
import "./style.css";

function App() {
  return <h1 className="heading">Namaste React</h1>;
}
```

### Advantages

* Easy to maintain
* Reusable
* Most common approach

---

## 2. Inline CSS

Styles are written directly inside JSX.

```jsx
function App() {
  return (
    <h1
      style={{
        color: "blue",
        fontSize: "30px",
      }}
    >
      Namaste React
    </h1>
  );
}
```

### Notes

* Style accepts a JavaScript object.
* CSS properties use camelCase.

Example:

```jsx
backgroundColor
fontSize
marginTop
```

---

## 3. CSS Modules

Provides locally scoped CSS.

### App.module.css

```css
.heading {
  color: red;
}
```

### App.js

```jsx
import styles from "./App.module.css";

function App() {
  return (
    <h1 className={styles.heading}>
      Namaste React
    </h1>
  );
}
```

### Advantages

* Avoids class name collisions.
* Component-specific styling.

---

## 4. Sass / SCSS

CSS preprocessor with additional features.

### Example

```scss
$primaryColor: blue;

.heading {
  color: $primaryColor;
}
```

### Features

* Variables
* Nesting
* Mixins
* Functions

---

## 5. Styled Components

CSS written inside JavaScript.

Install:

```bash
npm install styled-components
```

Example:

```jsx
import styled from "styled-components";

const Title = styled.h1`
  color: blue;
  font-size: 30px;
`;

function App() {
  return <Title>Namaste React</Title>;
}
```

---

## 6. Tailwind CSS

Utility-first CSS framework.

Example:

```jsx
<h1 className="text-blue-500 text-3xl font-bold">
  Namaste React
</h1>
```

Instead of writing CSS separately, styling is done using utility classes.

---

# Summary of Styling Methods

| Method            | Use Case              |
| ----------------- | --------------------- |
| External CSS      | Traditional styling   |
| Inline CSS        | Dynamic styles        |
| CSS Modules       | Component scoped CSS  |
| SCSS/SASS         | Advanced CSS          |
| Styled Components | CSS-in-JS             |
| Tailwind CSS      | Utility-first styling |

# 2. How Do We Configure Tailwind CSS?

The exact commands vary by version, but the Namaste React course commonly uses the following setup.

---

## Step 1: Install Tailwind

```bash
npm install -D tailwindcss postcss
```

---

## Step 2: Generate Config File

```bash
npx tailwindcss init
```

Creates:

```txt
tailwind.config.js
```

---

## Step 3: Configure Content Paths

```js
module.exports = {
  content: [
    "./src/**/*.{js,jsx}",
  ],
  theme: {
    extend: {},
  },
  plugins: [],
};
```

---

## Step 4: Add Tailwind Directives

Inside CSS file:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

---

## Step 5: Import CSS

```jsx
import "./index.css";
```

---

## Example

```jsx
function Header() {
  return (
    <h1 className="text-4xl font-bold text-green-600">
      Namaste React
    </h1>
  );
}
```

# 3. Meaning of Keys in `tailwind.config.js`

Example:

```js
module.exports = {
  content: [],
  theme: {},
  plugins: [],
};
```

---

## A) `content`

Tells Tailwind where to look for class names.

Example:

```js
content: [
  "./src/**/*.{js,jsx,ts,tsx}"
]
```

### Why Needed?

Tailwind removes unused CSS during build.

Without content paths:

```txt
Tailwind cannot detect classes.
```

and styles may not work.

---

## B) `theme`

Defines the design system.

Example:

```js
theme: {
  colors: {
    primary: "#3490dc"
  }
}
```

Used to customize:

* Colors
* Fonts
* Spacing
* Breakpoints
* Widths
* Heights

---

## C) `extend`

Used inside theme.

Adds new values without replacing defaults.

Example:

```js
theme: {
  extend: {
    colors: {
      brandBlue: "#1DA1F2",
    }
  }
}
```

Now:

```jsx
<div className="text-brandBlue">
```

works.

---

### Difference Between `theme` and `extend`

#### Wrong

```js
theme: {
  colors: {
    red: "#ff0000"
  }
}
```

Replaces all default colors.

---

#### Correct

```js
theme: {
  extend: {
    colors: {
      brandBlue: "#1DA1F2"
    }
  }
}
```

Keeps default colors and adds new ones.

---

## D) `plugins`

Used to add Tailwind plugins.

Example:

```js
plugins: []
```

Popular plugins:

```bash
npm install @tailwindcss/forms
npm install @tailwindcss/typography
```

Example:

```js
plugins: [
  require("@tailwindcss/forms"),
]
```

---

## Complete Example

```js
module.exports = {
  content: [
    "./src/**/*.{js,jsx}"
  ],

  theme: {
    extend: {
      colors: {
        primary: "#3b82f6",
      },
    },
  },

  plugins: [],
};
```

# 4. Why Do We Have `.postcssrc` File?

Tailwind CSS works through **PostCSS**.

PostCSS is a tool that processes CSS using plugins.

---

## What is PostCSS?

Think of it as:

```txt
Input CSS
     ↓
PostCSS
     ↓
Tailwind Plugin
     ↓
Final CSS
```

---

## Example `.postcssrc`

```json
{
  "plugins": {
    "tailwindcss": {}
  }
}
```

or

```json
{
  "plugins": {
    "@tailwindcss/postcss": {}
  }
}
```

(depending on Tailwind version)

---

## Why Is It Needed?

It tells PostCSS:

```txt
Use Tailwind plugin while processing CSS
```

Without it:

```txt
@tailwind base;
@tailwind components;
@tailwind utilities;
```

will not be converted into actual CSS.

---

## Flow of Tailwind Compilation

```txt
index.css
    |
    |-- @tailwind base
    |-- @tailwind components
    |-- @tailwind utilities
    |
    v

PostCSS
    |
    v

Tailwind Plugin
    |
    v

Generated CSS
    |
    v

Browser
```
