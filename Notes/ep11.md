# Chapter 11 - Data is the New Oil

## 1. What is Prop Drilling?

**Prop Drilling** is the process of passing data from a parent component to a deeply nested child component through multiple intermediate components using props.

### Example

```jsx
<App>
  <Parent user="Pardhu">
    <Child>
      <GrandChild />
    </Child>
  </Parent>
</App>
```

```jsx
function Parent({ user }) {
  return <Child user={user} />;
}

function Child({ user }) {
  return <GrandChild user={user} />;
}

function GrandChild({ user }) {
  return <h1>{user}</h1>;
}
```

Even though only `GrandChild` needs the data, `Parent` and `Child` must pass it down.

### Problems

* Makes code harder to maintain.
* Intermediate components may not need the data.
* Becomes cumbersome in large applications.

### Solution

Use **React Context** to share data directly without passing props through every level.

## 2. What is Lifting the State Up?

**Lifting State Up** means moving state to the nearest common parent so multiple child components can share and synchronize that state.

### Before

```jsx
<Child1 />
<Child2 />
```

Both children maintain their own state.

### After

```jsx
function Parent() {
  const [value, setValue] = useState("");

  return (
    <>
      <Child1 value={value} setValue={setValue} />
      <Child2 value={value} />
    </>
  );
}
```

The parent owns the state and passes it to children.

### Benefits

* Single source of truth.
* Easier synchronization between components.
* Better state management.

### Example from Namaste React

Accordion:

```jsx
const [showIndex, setShowIndex] = useState(null);
```

State is moved to the parent so only one category stays open at a time.

## 3. What are Context Provider and Context Consumer?

### Context Provider

The Provider supplies data to all components inside it.

```jsx
<UserContext.Provider value={{ loggedInUser: "Pardhu" }}>
  <App />
</UserContext.Provider>
```

### Context Consumer

The Consumer receives data from the nearest Provider.

#### Using Consumer

```jsx
<UserContext.Consumer>
  {({ loggedInUser }) => (
    <h1>{loggedInUser}</h1>
  )}
</UserContext.Consumer>
```

#### Using useContext (Modern Way)

```jsx
const { loggedInUser } = useContext(UserContext);
```

### Flow

```text
Provider
   ↓
Component A
   ↓
Component B
   ↓
Component C (Consumes Context)
```

No prop drilling is required.

## 4. If you don't pass a value to the Provider, does it take the default value?

### Yes.

When a Context is created, a default value can be provided:

```jsx
const UserContext = createContext({
  name: "Default User",
});
```

If no Provider exists above the component:

```jsx
const user = useContext(UserContext);

console.log(user.name);
```

Output:

```text
Default User
```

### Example

```jsx
const UserContext = createContext("Guest");
```

Without Provider:

```jsx
const user = useContext(UserContext);

console.log(user);
```

Output:

```text
Guest
```

With Provider:

```jsx
<UserContext.Provider value="Pardhu">
  <App />
</UserContext.Provider>
```

Output:

```text
Pardhu
```

### Important

The default value is used **only when no matching Provider is found above the component tree**.

### Quick Interview Answers

**What is Prop Drilling?**

> Passing data through multiple levels of components using props.

**What is Lifting State Up?**

> Moving state to the nearest common parent so multiple children can share it.

**What is Context Provider?**

> A component that provides context data to its descendants.

**What is Context Consumer?**

> A component or hook (`useContext`) that reads context data.

**Does Context use the default value if no Provider is present?**

> Yes. The value passed to `createContext()` becomes the fallback value.
